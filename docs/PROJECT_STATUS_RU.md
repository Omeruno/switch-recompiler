# Где находится Switch Recompiler

Актуально после пакета BMP, 2026-10-25. Технические подробности и следующая
задача: [активная карта](ACTIVE_ROADMAP.md), [handoff](AI_HANDOFF.md).
Полная [карта A–I](ROADMAP.md) остаётся инженерным планом.

**Программная база F0–F5 завершена по ограниченным критериям; аппаратная приёмка F ожидает проверки Switch.**
Запуск x86-программ, окна и графический вывод уже существуют. До широкой
совместимости программ, установщиков и игр остаются отдельные крупные работы.
Процент общей готовности и срок без конкретной матрицы приложений не определены.

| Крупный блок | Что уже есть | Что ещё нужно |
| --- | --- | --- |
| Исполнение x86, A/B/C | Интерпретатор, потоки, TLS, ожидания/события/HANDLE, корректное завершение; ограниченный этап C принят на Switch | Постоянные регрессии, совместимость пограничных случаев; полная NT-модель не входит в принятую границу |
| Совместимость Windows, D | PE EXE/DLL, импорты, загрузка/выгрузка, часть SEH, большой набор Win32/CRT | Защита памяти, полный unwind/SEH, COM и API, которые потребуют реальные приложения |
| Графика, E | CPU GDI, GPU-вывод/fallback, слои/кэши, метрики и публичные проверки пикселей | Приёмка текущей сборки на Switch, дальнейшая интеграция слоёв и измерения реальных нагрузок |
| **Среда, F — программная база готова** | Постоянные C/S/R, desktop/Пуск/проводник, один активный guest, возврат после выхода/ошибки; реальные папки/файлы, Copy/Paste, контекстные меню, настройки, TXT и ограниченный просмотр BMP | Дерево, реальные Desktop/Start .lnk, retained-композиция и сквозное сохранение/ошибки/повторное открытие теперь реализованы; аппаратная приёмка отдельно |
| Ускорение, G | Ограниченное профилирование частот инструкций/host calls | Измерить репрезентативные программы, выбрать подтверждённую оптимизацию; полноценного dynarec пока нет |
| Игровая графика и продукт, H/I | Сборки, диагностика и тестовая инфраструктура | DirectDraw/Direct3D, матрица совместимости, конфигурация и доведение продукта |
| Установка/архивы | [План установщиков, ярлыков и архивов](F_INSTALL_AND_ARCHIVES.md) | Реальные поддержанные installer EXE, папки установки, Desktop/Start shortcuts; ZIP, затем RAR/другие форматы |

## Что изменилось в последних пакетах

Ранее файлы можно было увидеть/передать приложению, но многих обычных действий
с ними не было. Теперь программно работают:

1. Создание папок, rename/delete, реальные свойства и подтверждение удаления.
2. Проверяемое копирование, Copy/Paste с прогрессом/отменой и контекстные меню.
3. Сохранение сортировки/ассоциаций между перезапусками и их управление в Пуске.
4. TXT: создать, прочитать, изменить строки, сохранить с резервной копией,
   отказаться от закрытия несохранённого текста. [Пределы](F_TEXT_DOCUMENTS.md).
5. BMP: реальный файл -> декодированные пиксели -> просмотр/100%/прокрутка.
   Публичная x86-программа рисует GDI, сохраняет BMP, проводник его находит,
   новая гостевая сессия читает тот же файл. [Пределы](F_IMAGE_DOCUMENTS.md).

Эти пакеты расширяли функции среды. Они сами по себе не расширяют список
совместимых игр и не дают ускорения интерпретатору. Поддерживается один гостевой
Process с его окнами; несколько одновременно запущенных EXE ещё не реализованы.
TXT/BMP — собственные native-инструменты оболочки, а не заявление о полной
совместимости Notepad/Paint или готовой копии Windows XP.

## Пройденный программный рубеж

**F5: открыть приложение из Пуска -> сохранить документ в My Documents ->
вернуться -> найти -> открыть снова, с настоящими ошибками хранения.**

Этот путь теперь проверяется вместе с деревом, ярлыками, args/CWD, отказами
записи, слоями и повторными гостевыми сеансами. Общий отчёт содержит 22 группы
программных свидетельств и хеши публичных EXE; [критерии и ограничения](F_ACCEPTANCE.md).
FlushFileBuffers больше не возвращает ложный успех: проверяет HANDLE/доступ,
fflush/fsync и сообщает ошибки. Итоговый статус — PASS_SOFTWARE_PENDING_HARDWARE.

После этой вехи: закрывать измеримые пробелы совместимости D на публичных
примерах, переходить к измерениям G и выбранной оптимизации. Установщики/ярлыки/
архивы остаются отдельным записанным расширением; DirectDraw/D3D — отдельная
большая программа. Дальнейшая Luna-полировка отложена по решению пользователя.

Host/CI PASS подтверждает программные проверки. Текущие Paint/GPU/fallback/
Lite/ввод/повторные запуски на физическом Switch остаются отложенными.
Локального devkitA64/libnx нет, NRO собирает CI. Восстановленную SD повторно
не диагностируем. Вехи закрываются проверенным поведением, не числом коммитов.


Добавлены реальные пользовательские ярлыки Desktop/Start и дерево папок,
согласованные ProgramFiles/CSIDL_PROGRAMS и удерживаемые native/guest слои.
Установщики/ZIP/RAR из будущего расширения не объявлены готовыми.


## Следующий этап после программной F: измерения G1

По наблюдению пользователя Paint и большое поле сапёра замедляют работу. GPU
уже выводит и композитит окна, но GDI пока рисует на CPU. Добавлен [публичный
PE-тест измерений](G1_MEASUREMENTS.md): вычисления, плитки и линии, проверка всех
пикселей, повторные замеры фаз и стоимости счётчиков. Это начало этапа ускорения,
пока без обещания роста FPS на Switch. Дальше — измерения реальных консольных
нагрузок и обоснованное ускорение GDI/интерпретатора; перенос GDI на GPU должен
сохранить ROP, чтение пикселей и software fallback. Внешний вид Luna ещё требует
доработки. Pinball x86 пока упирается в отсутствующие API реестра (этап D).


G2: добавлен первый реальный быстрый путь GDI — обычное 32-битное копирование
SRCCOPY без масштабирования, с сохранением отсечения, данных оконных слоёв и
CPU readback. Сравнивается с прежним алгоритмом в одной сборке и публичном
x86-тесте. Это CPU-оптимизация, не готовое GPU-GDI; FPS Switch пока не измерен.
Опциональные фазы отчёта подготовлены для будущих измерений. Сейчас никаких
действий/новых аппаратных тестов от пользователя не требуется.


Обновления Claude (пять коммитов Luna) сохранены: обои, значки, проводник и Пуск.
Исправлен стык нового размера окна с композицией/вводом при работающем EXE.
G3 добавляет изолированный OpenGL-прототип заливки/копирования с проверкой
пикселей, CPU readback и восстановления после потери контекста. В Paint он
пока не включён: далее G4 — согласованный мост окон/памяти/вывода. Это не
объявление полного GPU-GDI или готовности всех операций окна XP.


G4a: несколько GPU-поверхностей с защитой от устаревших идентификаторов и
выводом из GPU-текстур без чтения на CPU при каждой композиции. Проверены
перекрытие/масштабирование,1280x720, CPU-барьеры и восстановление при ошибках.
Это пока отдельный проверяемый мост; живой Paint не переключён. Следом G4b —
пакетирование команд и согласование с окнами/памятью/основным выводом.


G4b.1: соседние неперекрывающиеся GPU-заливки объединяются в один instanced
draw. Порядок пересечений и копирований сохранён; есть сравнение с прежним
путём по пикселям, числу вызовов и времени host-циклов. В публичном тесте
64 заливки превращаются в1 draw; для пересечений остаются64. Живой Paint
пока не переключён: G4b.2 — согласование с окнами/памятью/основным выводом.
