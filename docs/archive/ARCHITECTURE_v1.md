# Архитектура switch-recompiler

Как `.exe` из Windows XP превращается в картинку на экране Switch.
Название историческое: перекомпиляции нет, это интерпретатор с HLE
(high-level emulation) системных функций.

```
romfs:/winmine.exe
   │
   ▼
loader/pe_parser        разбор PE32, секции → плоский образ по ImageBase
loader/resource_parser  ресурсы: меню, диалоги, битмапы, строки, WAVE
   │
   ▼
win32/iat_patcher       каждый импорт в IAT → «host-адрес» 0xF0000000 + i*0x10
   │                    (данные CRT вроде _acmdln → ячейки crt_globals)
   ▼
cpu/guest_memory        одна плоская область:
   │                    [образ][стек 64К][TEB][CRT-глобалы][MFC-состояние][куча]
   ▼
decoder/x86_decoder  →  cpu/interpreter     пошаговое исполнение x86
   │                         │
   │         EIP попал в 0xF0000000+ ? ──► win32/host_functions:
   │                                         Impl_<Имя>(cpu, mem): читает
   │                                         аргументы со стека, делает работу,
   │                                         чистит стек по stdcall/cdecl,
   │                                         кладёт результат в EAX
   ▼
win32/gdi, window_manager, message_loop, virtual_registry, dialog/menu_parser
   │
   ▼
main.cpp: PumpHostFrame() — ввод (тач/стик/кнопки) → WM_* в очередь;
          GDI-экран + наш UI-оверлей (меню, тулбар, палитра, курсор) →
          фреймбуфер libnx
```

## Слои

### Загрузчик (`source/loader/`)
- `pe_parser` читает заголовки PE32, секции и таблицу импорта и
  раскладывает образ по `ImageBase`. Релокаций и таблицы экспорта нет:
  поддерживается только один `.exe` по его родному адресу, без DLL.
- `resource_parser` проходит дерево ресурсов и находит ресурс по типу и
  ID. Через него грузятся меню, диалоги, `RT_BITMAP` и звуки `WAVE`.

### CPU (`source/cpu/`, `source/decoder/`)
- `x86_decoder.cpp` декодирует 32-битные инструкции в структуру
  `Instruction` (мнемоника, операнды, ModRM/SIB, префиксы). Поддержано
  около 45 мнемоник целочисленного подмножества (MOV/ALU/сдвиги/MUL/DIV,
  переходы, строковые STOS/MOVS/CMPS с REP). FPU (x87), MMX и SSE нет
  совсем: Сапёру и Paint они не понадобились.
- `interpreter.h` исполняет `Instruction` над `CpuState` (регистры, EFLAGS)
  и `IGuestMemory`. Сегменты FS/GS указывают на фейковый TEB (SEH-цепочка
  и границы стека, этого хватает CRT).
- `guest_memory.h` — `FlatGuestMemory`, один сплошной буфер с проверкой
  границ. Ошибка доступа фатальна и печатает адрес.

### HLE Win32/MFC (`source/win32/`)
- `host_functions.cpp` (~4,9 тыс. строк) — таблица реализаций
  `{"DLL", "Имя", размер_аргументов, соглашение, &Impl_*}`. Нереализованная
  функция попадает в общую заглушку, которая пишет имя и адрес возврата и
  возвращает 0. Это основной инструмент поиска следующего бага.
- MFC42u импортируется **по ординалам**. Имена и сигнатуры восстановлены
  скриптом `tools/mfc_abi.py` в таблицу `mfc42u_abi_table.h`. От неё
  зависит, сколько байт стека заглушка должна снять: ошибка здесь сдвигает
  стек вызывающего кода (так был найден краш Кисти, ординал 5784).
- Ключевые MFC-функции написаны на хосте: `AfxWinMain`, `CWinThread::Run`
  (ординал 5710), `AfxWndProc` с разбором message map, а также `CDC`.
  Внутренние объекты MFC (`CDC`, vtable) синтезируются по минимуму.
- `gdi.cpp` — программный растеризатор: DC, перья, кисти, битмапы,
  `BitBlt`, `LineTo`, `Rectangle`, `Ellipse`, `SetPixel`/`GetPixel`,
  текст растровым шрифтом.
- `window_manager`, `message_loop` — окна, классы, очередь сообщений
  (`Post`, `Pop`, `PeekFiltered` с честным `PM_NOREMOVE`). Вложенный вызов
  гостевой функции (`CallGuestFunctionStdcall`) нужен для WndProc,
  `DialogBox` и `UpdateWindow`.
- `virtual_registry` — реестр в памяти. Сапёр хранит в нём настройки и
  рекорды.
- `dialog_parser`, `menu_parser` — разбор ресурсов `DIALOG` и `MENU` для
  нашего собственного UI.

### Switch-фронтенд (`source/main.cpp`)
- Выбор `.exe` из `romfs:`, запуск `RunInterpreter`.
- `PumpHostFrame()` вызывается из цикла сообщений гостя. Она опрашивает
  ввод, превращает его в `WM_LBUTTONDOWN`/`WM_MOUSEMOVE`/`WM_LBUTTONUP`
  (тач, стик и A), перехватывает клики по меню и диалогам и рисует кадр.
- Интерфейс Paint (меню, тулбар из RLE4-битмапа ресурса 859, 28-цветная
  палитра) рисуется **нашим** оверлеем поверх холста. Настоящие `CToolBar`
  и `CStatusBar` из MFC не строятся. Выбор инструмента и цвета передаётся
  через сигналы `g_requestedToolId` и `g_requestedForegroundColor` и
  применяется вызовом настоящего кода paint.exe (`SelectTool` по адресу
  `0x1015199`).

## Тесты
- `tests/test_*.cpp` плюс `tests/data/test*.bin` — маленькие x86-программы,
  которые через интерпретатор вызывают реестр, окна, WndProc, вложенные
  host-вызовы и GDI. Запуск: `sh tools/run_host_tests.sh`, и тот же
  скрипт в CI.
- `tests/trace_paint.cpp` повторяет настройку `RunInterpreter` без
  `switch.h`, прогоняет `paint.exe` на хосте, симулирует ввод и
  сохраняет экран в `paint_output.ppm`.

## Известные ограничения архитектуры
- Нет загрузки DLL (`LoadLibraryA` возвращает фиктивный хендл),
  релокаций, потоков, настоящей обработки SEH-исключений, x87/SSE.
- Один процесс, одно «настоящее» окно. Оконный менеджер упрощён.
- Интерпретатор без JIT: для Сапёра и Paint хватает, для 3D-игр нет.
- MFC эмулируется вручную, и это главный источник багов (подробности
  в `POSTMORTEM.md`).
