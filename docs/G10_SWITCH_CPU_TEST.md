# G10 — отдельная проверка CPU на Switch

Статус: **PENDING_USER_SWITCH_RUN**. Облачные проверки не заменяют консоль.

1. В успешном CI рабочей ветки скачай артефакт `switch-cpu-batch-validation`.
   Внутри находится `build-host/cpu-batch-validation.zip`; распакуй именно его
   в корень SD с сохранением папок. Обычный NRO/игровые файлы не заменяются.
2. Запусти `/switch/cpu-batch-validation/cpu-batch-validation.nro` через hbmenu.
   На текстовом экране будут CPU batch validation и полный SHA сборки.
3. Дождись автоматических19 проб и итогового PASS/FAIL/UNAVAILABLE.
   PLUS отменяет. Частоты тест не меняет; сохрани один профиль питания/разгона.
4. Пришли `/switch-recompiler-cpu-validation.txt` из корня SD и укажи модель,
   applet/запуск через игру и профиль частот. При зависании — уже записанный
   отчёт и фото экрана; начало каждой пробы сохраняется до её выполнения.

Триггер `/switch-recompiler/cpu-validation.flag` со значением1 потребляется и
становится0. Для повтора скопируй его из ZIP снова. Обычные cpu-native.flag,
cpu-native-batch.flag и cpu-reference.flag тест не меняет: режимы выбираются
внутри одинакового публичного теста, включая обязательный эталон.
Если вместо теста открылась оболочка, проверь NRO и расположение триггера.

Пакет содержит точный опубликованный SHA, NRO с этим SHA, публичные PE/DLL,
manifest с размерами/SHA256/FNV1a64 и русскую инструкцию. Отчёт содержит SHA,
платформу, тип applet/режим/HOS, хеши PE/DLL,19 проб с реальным временем,
инструкциями/квантами/native/batch и участием DLL/WndProc/APC/worker.
Host/QEMU помечаются HOST_OR_QEMU_NOT_SWITCH и не принимаются за железо.

Приёмка: совпали независимые результаты/файл и полный census/кванты,
реально выполнены native и batches, код освобождён, все19 проб PASS.
Скорость отдельно сравниваем по медианам пяти измеренных троек; PASS сам по
себе не обещает выигрыш. UNAVAILABLE означает отсутствие рабочего native-пути,
а не успех. При неполном отчёте аппаратная приёмка остаётся открытой.

Это CPU-проверка: FPS Pinball/Paint, GPU, ввод и повторы приложений требуют
отдельного опыта и остаются отложенными. SD и старый JIT42 повторно не проверяем.
