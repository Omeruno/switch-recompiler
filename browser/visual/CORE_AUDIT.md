# Аудит ядра браузера Switch — 6 ноября 2026

Ветка: `feature/switch-browser`. Исходная база аудита: visual 0.4.1; результаты блоков 0.5.0–0.7.0 описаны ниже.
Новую версию 0.4.1 пользователь ещё не проверял. Переносы и растущие ошибки
описаны без списка URL/отчёта для каждой страницы, поэтому ниже отделены
подтверждённые дефекты кода от возможных причин отказа конкретных сайтов.

## Как устроены современные браузеры

Chromium/Blink, Firefox/Gecko и WebKit разделяют несколько задач:

1. Сеть, HTTPS, cookies, кэш и правила доступа загружают документы и ресурсы.
2. HTML-парсер строит DOM; CSS-парсер и каскад вычисляют стили.
3. Layout рассчитывает размеры, строки, переносы, flex/grid и позиции.
4. Paint формирует команды рисования; raster/compositor превращают их в кадр.
5. JavaScript обращается к тому же DOM через Web API. Event loop согласует задачи,
   Promise microtasks, события, таймеры и обновления изображения.
6. Медиа, GPU, workers и память WASM имеют отдельные подсистемы.

Это обобщение первичных документов [Chromium RenderingNG][1], [Firefox Rendering][2],
[WebKit Introduction][3] и [HTML event loops][4]. Наличие JavaScript-движка само по
себе не предоставляет DOM, сеть, видео или GPU. Разделение процессов и защита памяти
в больших браузерах также не появляются от подключения библиотеки разметки.

## Где сейчас находится наше ядро

| Подсистема | Реализовано | Чего существенно не хватает |
|---|---|---|
| Сеть | curl-multi, HTTPS/CA, cookies, GET, навигационные POST, ограничения CSP | полный Fetch/CORS, POST fetch, XHR, WebSocket, HTTP-кэш, MIME/charset-политики |
| Документ | Gumbo + удерживаемый native DOM litehtml | полные Web IDL интерфейсы DOM, полный CSSOM, iframe, editing/selection/accessibility |
| CSS/layout | каскад, обычный поток, таблицы, flex, media queries, размеры и поля | Grid, полное современное intrinsic sizing, дополнительные правила текста, transforms |
| Paint | SDL, DejaVu, PNG/JPEG/WebP, заливки, часть границ и градиентов | SVG, web fonts/shaping/fallback, полные тени/outline/clip, display list/compositor |
| JS | QuickJS, native DOM bridge, события, таймеры, Promise, GET fetch, classic async/defer, Mutation/Resize/IntersectionObserver | модули, workers, множество остальных Web API |
| Планирование | раздельные задачи/microtasks/rAF, асинхронная сеть, бюджеты JS/observer и типизированные resource revisions | потоковая загрузка/parser scheduling, полная очередность стандарта, точечная style/layout-инвалидация |
| Игры/медиа | отдельный WASM probe | JS/WASM game imports, WebGPU/WebGL, видео/аудио, MSE/WebRTC, игровые события |
| Изоляция | квоты и интерпретаторы | полноценные границы процессов/песочницы, модель безопасности современного браузера |

Текущие квоты — 64 ресурса, 16 начальных classic scripts, 128 KiB на скрипт,
32 MiB на JS — могут останавливать современные сайты до их инициализации.
Слепое повышение всех лимитов не устраняет отсутствующие API и требует измерений
памяти на Switch. Это отдельная причина, которую должен показывать отчёт.

**Вывод:** litehtml остаётся рабочим кандидатом для ограниченного визуального
браузинга. Его авторы [не рекомендуют использовать библиотеку как полное
браузерное ядро][5]. Локальные исправления полезны, но не являются доказательством,
что на этой основе уже доступен полный современный браузер или клиент WoW.

## Подтверждённые дефекты и изменения 0.5.0

### Раскладка

- В закреплённом litehtml отсутствовал flex `gap`. Добавлены `gap`, `row-gap`,
  `column-gap`, каскад/переменные, относительные единицы и проценты для реализованных
  расчётов. Интервалы участвуют в переносе строк и распределении места, не сжимаются
  как flex items, работают для row/column, reverse/wrap и `justify-content`.
- Flex render item не регистрировал себя для native DOM geometry. Контейнер мог
  возвращать нулевой `getBoundingClientRect()`, хотя его дети отображались.
- Автоматические отступы делились на число сторон всех элементов, затем добирались
  целыми пикселями. Исправлено распределение между фактическими auto margins.
- Счётчик неподдержанных операций paint копился между кадрами. Теперь это число
  операций за последний кадр; ошибки декодирования изображений учитываются отдельно.

Использованы правила [CSS gaps][6]. Наши 20 собственных fixtures проверяются при
ширине 1280 и 640: 120 прямоугольников сравниваются с Chromium **151.0.7922.34**,
допуск 0.1 CSS px. Reference получен через Playwright; версия и SHA256 HTML
записаны в TSV. Это координатные проверки конкретных примеров, не прохождение
полного WPT. Метод опирается на идею независимого эталона из [WPT reftests][7].

Ограничения: это **flex gaps**, не Grid или multicol; complex `calc()`-выражения
и все циклические intrinsic-sizing случаи не покрыты. `normal` во flex равен нулю;
проценты без определённой высоты разрешаются с нулевой базой. Полная поддержка
переносов текста, baseline, writing modes и всех flex edge cases не заявлена.

### Отчёт ядра

Открыть: **L**, касание строки состояния, на компьютере **F1**. B закрывает;
касание левой/правой половины листает страницы. При открытии сохраняется снимок:
`/switch/switch-visual-browser/core-report.txt`.

Отчёт разделяет HTTP, TLS, транспорт, квоты, блокировки, декодирование изображений
и группы проблем JavaScript. Повтор одного класса ошибки группируется, а не
выглядит как новая причина на каждом кадре. Максимум 24 группы, число повторов
насыщается на 65535; снимок перезаписывается, не копится бесконечным журналом.

В снимке остаются только origin ресурса и технический класс/категория JS-сбоя.
Нет URL-путей/query, сообщений и stack traces JS, HTML, cookies, паролей, значений
полей или тела POST. Это осознанно ограничивает детализацию: два разных TypeError
одного origin могут оказаться одной группой. Для точного воспроизведения нужен
конкретный URL и минимальный пример; сам счётчик не доказывает причину сбоя сайта.

## Как двигаться к полноценному браузеру

### Ближайшие обязательные блоки

1. Собирать отдельные воспроизводимые примеры для Google/Keldurn/VK/YouTube:
   ресурс/политика, исключение JS, неверный прямоугольник или отсутствующий API.
   Новые layout-дефекты проверять против Chromium/Firefox, а не подгонять CSS сайта.
2. Привести event loop, script scheduling, ошибки/Promise и инвалидацию к отдельным
   чётким этапам. Разделить изменения DOM, style/layout, ресурсов и paint; исключить
   полный rebuild при каждом завершении некритичной загрузки.
3. Расширять DOM/CSSOM и сетевые API по fixtures и реальным вызовам сайтов.
   Отдельно проектировать modules/workers, общий lifecycle и отмену навигации.
4. Для Grid, shaping, SVG, compositor, GPU и медиа принять проверяемое решение
   о дальнейшем layout/runtime engine. Это крупная зависимость игрового браузера.

### Выбор следующего ядра — контрольная точка, а не обещанный перенос

| Вариант | Что даёт | Что требуется доказать на Horizon |
|---|---|---|
| Продолжить litehtml + QuickJS | Уже работающий NRO и управляемый объём | стоимость реализации недостающих стандартов, нагрузка полного rebuild |
| WPE/WebKit | Более полный интегрированный web stack | зависимости ОС/потоков/IPC, backend поверхности и графики, память, сборка и запуск |
| Servo | Интегрированные DOM/layout/WebRender, [WebGPU через wgpu][8] | Rust/toolchain, SpiderMonkey, OS abstractions, GPU/context/backend, память и поддерживаемые API |
| Chromium/Blink | Широкая совместимость web platform | системные зависимости и процессная модель, build/embedding, GPU/media backend и бюджет памяти |

Документы [Servo architecture][9] и [WebKit2][10] описывают их подсистемы, а не
готовую поддержку Nintendo Switch. ARM64 сам по себе не доказывает переносимость
на Horizon. Ни один из этих вариантов пока не собран/не проверен нами на Switch.

Минимальный критерий выбора: воспроизводимая сборка под Horizon, один отрисованный
документ и native input, HTTPS, JS/DOM mutation, замер RAM/кадра и перечень GPU/media
зависимостей. Только после этого менять рабочий renderer по умолчанию. Без этого
замена ядра в плане останется названием библиотеки.

VK «устаревший браузер» может зависеть от UA, feature detection или ошибки запуска;
для текущей страницы причина ещё не доказана. Отказ YouTube нельзя по имеющимся
данным приписать только региональному ограничению. VPN отложен пользователем.
WebGPU/WASM игры и облачное видео остаются отдельными неподтверждёнными этапами.

## Выполненный следующий блок — 0.6.0

Внесено разделение таймеров, microtasks и rAF. Очередь микрозадач проверяется
после каждой задачи/кадрового callback; незаконченная очередь продолжается до
следующей задачи. Добавлены queueMicrotask, currentScript, отдельные стадии
interactive → defer → DOMContentLoaded → complete/load и обработка отклонений
Promise. Ожидание внешнего скрипта больше не останавливает таймеры/fetch.

Завершения CSS, изображений и невизуальных ресурсов учитываются раздельно.
JSON/скрипт без DOM-изменений не пересобирает CSS; изображение вызывает только
layout. Изменения DOM объединяются до конца шага; чтение геометрии может потребовать
синхронного refresh. Число CSS/layout-проходов доступно в отчёте L.

Новые проверки используют настоящий Browser и TLS-сервер с задержками: порядок
async/defer, таймер при ожидании, события загрузки, сохранение DOM/ввода, изображение
с intrinsic size, поздний CSS и отмена старых callbacks при навигации.

Ограничения остаются: это планирование после полного разбора HTML, без streaming
parser-blocking, исполнения динамически добавленных скриптов, modules/workers,
полного порядка всех task sources и всех load-blocking правил. Квант UI мягкий
8 мс между callbacks; лимит JS — 50 мс на начальный скрипт/callback, максимум
32 jobs на checkpoint перед продолжением в следующем шаге. На хосте учитывается
CPU-время потока, на Switch — монотонное прошедшее время. Тяжёлые native вызовы
не прерываются JS-хуком. Это измеримое улучшение существующего ядра, а не закрытие
всего пункта о планировании или переход на новое ядро.

## Следующий связный блок — 0.7.0

Динамические classic scripts и MutationObserver соединены с тем же native DOM.
Inline-вставка выполняется синхронно; внешние скрипты имеют async/ordered очереди,
состояние запуска закреплено за элементом, а навигация отменяет старую сессию.
Записи observer формируются при изменениях атрибутов, текста, дочерних узлов,
пакетных вставках и DocumentFragment. Доставка идёт через microtasks, с фильтрами,
старыми значениями, временными наблюдениями снятых поддеревьев и ограничениями очереди.

Правила проверены по [DOM MutationObserver](https://dom.spec.whatwg.org/#mutation-observers)
и [HTML script processing](https://html.spec.whatwg.org/multipage/scripting.html#prepare-the-script-element).
Один и тот же собственный набор поведенческих проверок выполнен в нашем runtime
и Chromium; это не прохождение полного WPT. Сборка включает офлайн-проверку для
Switch и отдельную памятку TESTING.md.

Санитайзер обнаружил чтение неинициализированного font_style при стилизации
innerHTML у нового detached-родителя. В закреплённый patch добавлен режим отложенной
стилизации фрагмента: создание DOM отделено от следующего refresh стилей.

Это закрывает согласованный блок dynamic scripts + MutationObserver в описанном
подмножестве. Modules/workers, ResizeObserver/IntersectionObserver, полный Fetch/CORS,
XHR/WebSocket, Grid, media/GPU и перенос полного движка остаются в дорожной карте.

## Проверка на Switch и исправление 0.7.1

Пользователь отмечает ускорение 0.7.0. На фото play.keldurn.com виден
ReferenceError об отсутствующем HTMLScriptElement; проверка безопасности не
завершилась. Отдельно Google показывает страницу отказа входа с сообщением о
неподдерживаемом JavaScript/браузере. Причина отказа сервисов целиком не установлена.

Исправлены типы native DOM-обёрток, цепочки прототипов, Script/Element property
descriptors и Document factories. Одна общая Node-обёртка больше не подменяет все
типы элементов. Добавлены Text/DocumentFragment constructors и корректные отрицательные
ответы supports() для неподдержанных модулей/import maps. Общий сценарий проверен
в Chromium и native runtime; вывод/хэш хранятся рядом с fixture.

Для включённого JS noscript скрывается, а скрипты внутри него остаются неактивными.
Полный HTML scripting tokenizer и остальные браузерные API остаются за рамками
этой правки. Успешный вход Google/проверка безопасности на устройстве не заявляются.

## Адаптивная вёрстка — 0.8.0

Добавлены ResizeObserver (content/border boxes, очередь после rAF, ограниченный
цикл по глубине дерева) и IntersectionObserver (экран/элемент, пороги, rootMargin,
overflow, отдельная очередь задач). Расширены MediaQueryList, resize/scroll и
прокрутка из JS с передачей координат в настоящий Browser view. Старые ссылки
на объекты вёрстки очищаются при обновлении CSS: найденный дефект давал нулевую
геометрию после первой смены стиля. BoundingClientRect теперь включает рамки и
отступы. В локальном демо появился раздел для проверки без сети.

Сценарий сравнения с Chromium проверяет размеры, скрытие/удаление/возврат,
пороги/обрезку, пиксельные поля корня, фиксированные координаты и media events.
Процентные rootMargin проверяются отдельно по спецификации (база — ширина корня);
эксперимент с Chromium 151 показал базу-высоту для вертикальных процентов. Это
расхождение явно сохранено в README, полного совпадения не заявляем. Дополнительно
проверяются лимиты, takeRecords, циклы и уничтожение callback при навигации.

SVG/transform/multifragment, device pixel box, intersection visibility/occlusion,
scrollMargin и smooth scrolling не реализованы. Наблюдатели не закрывают Grid,
модульный JS, сети, GPU/медиа и вход на защищённые сайты.
