# Прогон Switch Visual Browser 0.11.1

Заменить `/switch/switch-visual-browser.nro`. Запустить через игру с удержанием R.
Обновление системы не требуется. Браузерная прошивка Nintendo не используется.

## 1. Проверка без Wi-Fi

На стартовой странице найти раздел **«Проверка динамики»**.

| Действие | Ожидаемый результат |
|---|---|
| Нажать «Запустить проверку» | «Запуск: 1», «Изменений: 2», «Готово» |
| Нажать ещё раз | «Запуск: 2», «Изменений: 4», «Готово» |
| Обновить Y и повторить | Новый документ снова начинает с запуска 1 |
| Перейти в другое место страницы и вернуться | Счётчики сохраняются до навигации/обновления |
| Повторить через левый стик + A | Тот же результат, без случайного двойного запуска |

Это вместе проверяет загрузку отдельного файла скрипта, выполнение нового элемента,
уведомление MutationObserver об изменениях DOM, события load и перерисовку.
Картинки, поля ввода, выбор вариантов и русский текст также должны работать.

## 2. Навигация и управление

- Прокрутить сенсором и правым стиком, приблизить двумя пальцами.
- Переключить ширину страницы Minus; повторить запуск проверки.
- Открыть другой HTTPS-сайт через X, вернуться B и открыть демо.
- На каждой новой загрузке нет старых callbacks и зависших меню.

Для длинного прогона достаточно 10–15 минут с несколькими переходами, вводом
текста и возвратами. Отметить вылет, зависание, пропадание текста/картинок или
рост тормозов после нескольких переходов.

## 3. Реальные сайты

Проверить Google и `https://keldurn.com/ru/`, затем сайты, где раньше было больше
ошибок. Для каждого отметить:

1. Какой URL открывали и какое действие выполняли.
2. Есть ли поле ввода, сохраняется ли введённый текст при подгрузке страницы.
3. Реагируют ли кнопки и появляются ли динамические элементы.
4. Открыть **L** и сохранить отдельную копию отчёта для этого сайта.

Путь: `/switch/switch-visual-browser/core-report.txt`. Каждый новый вызов L
перезаписывает снимок. Можно переименовать копии в `google.txt`, `keldurn.txt` и т. п.
В отчёте должны быть версия **0.11.1**, категории загрузки/JS и счётчики CSS/layout.
Если проблема видна на экране, полезен скриншот или фото вместе с отчётом.

При вылете дополнительно сохранить
`/switch/switch-visual-browser/visual-report.txt`; сетевые стадии записываются в
`/switch/switch-visual-browser/network.log`.

## Границы этого прогона

Добавлены динамические **classic** scripts, MutationObserver, ResizeObserver и
IntersectionObserver. Для import maps/воркеров, полной модели CORS/cookies, Grid, WebGPU и
видео остаются отдельные блоки. Скрипты с непроверяемым integrity блокируются;
crossorigin для внешнего origin также пока не поддерживается. Игровой клиент WoW
ещё требует большого JS/WASM/GPU блока. Проверка VPN отложена пользователем.

На реальных сайтах проверить появление контента при прокрутке и смене ширины.

## Новый блок 0.10.0: модульная страница

1. В «Демо» открыть «Модульная страница»: статус должен стать «Модули готовы».
2. Нажать «Запустить модуль» дважды: «Запуск модуля: 1», затем «…: 2».
3. Переключить ширину через − и нажать снова: счётчик продолжает расти.
4. Перезагрузить демо: модульный счётчик начинается заново. Интернет не нужен.
5. На сайте повторить страницу с type=module/import и сохранить отчёт L при ошибке.

Поддерживаются URL-импорты JS и top-level await. Bare imports/import maps, Workers,
WebSocket и JS↔WASM/GPU ещё не подключены; вход и запуск игры не подтверждены.
Ошибки модуля теперь видны в строке JS; в отчёте сохраняются класс/стадия без текста
ошибки, query-параметров и значений полей.


## Новый блок 0.11.0: постоянное сетевое соединение

Сначала выполнить проверку **«Модульная страница»** из предыдущего блока:
счётчик должен увеличиваться при повторных нажатиях без перезагрузки.

Затем включить Wi-Fi и открыть **«Сетевая проверка WebSocket»** внизу демо:

1. Нажать **«Соединиться»**. Дождаться сообщения об открытом соединении.
2. Нажать **«Отправить проверку»** несколько раз. Число полученных сообщений
   должно увеличиваться; отправляется только фиксированная тестовая строка.
3. Нажать **«Закрыть»**: ожидается код 1000 и отметка «корректно».
4. Снова соединиться, прокрутить/приблизить страницу, затем перейти на другой сайт
   и вернуться на демо. Старое соединение не должно менять новую страницу.
5. При проблеме сохранить **L → core-report.txt** и указать, на каком шаге она
   возникла. Группа `websocket / tls`, `handshake`, `transport`, `timeout`, `policy`
   или `…-limit` помогает различить причины. Это не доказывает причину отказа сайта.

В поле изначально указан публичный echo-сервер. Его доступность не гарантирована;
при необходимости можно ввести другой совместимый `wss://` endpoint. Сервер
может требовать свой подпротокол/авторизацию, которых у этой простой демо-формы нет.
Без Wi-Fi проверка модулей должна работать, сетевая проверка может завершаться
ошибкой, а управление страницей должно оставаться доступным.

После демо повторить Keldurn/Google и сохранить отдельные отчёты. Успешный
WebSocket-тест не означает запуск игры или прохождение авторизации: JS↔WASM,
workers и GPU ещё не подключены. Не пересылайте пароли или содержимое сообщений;
в отчётах браузер их не сохраняет. На устройстве версия 0.11.0 ещё не проверена.

## Игровой блок 0.12.0 — проверка на Switch

1. Заменить `switch-visual-browser.nro`, запустить через игру с R (title override).
   Прошивку обновлять не требуется. Открыть Демо → **Игра WASM** → **Запустить игру**.
   Эта игра работает без Wi-Fi. Должны появиться сетка, голубой герой и жёлтый огонёк.
2. Коснуться поля и вести героя к огоньку. Поле должно получать касания без
   прокрутки страницы; при сборе огонька счётчик увеличивается и цель перемещается.
3. Выбрать поле, нажать R: движение левым стиком/крестовиной, A/B — ускорение,
   Minus — сброс, Plus — пауза/продолжение. ZL + ZR + Plus возвращает управление
   браузеру. После этого Plus снова закрывает приложение.
4. Проверить кнопки «Пауза», «Продолжить», «Сбросить игру», изменение масштаба и
   прокрутку вокруг поля. Затем уйти на другой сайт и вернуться: игра должна
   начинаться заново, старые кадры/кнопки не должны работать на новой странице.
5. Нажать L вне игрового захвата. В core-report есть счётчики WASM, Canvas,
   загрузок кадров и traps. При сбое прислать core-report.txt и visual-report.txt.
   Не присылайте пароли, cookies.txt или storage.bin.

Это проверка связки WASM → Canvas → ввод, а не подтверждение запуска Keldurn или
эмуляторов gam.onl. WebGPU/WebGL, web workers/shared memory и аудио ещё отсутствуют.
Главный риск перед выпуском — расход памяти и скорость интерпретатора на устройстве;
host-тесты не заменяют эту проверку.

Host: `ctest --test-dir browser/visual/build/host --output-on-failure`.
Дополнительный эталон с Playwright и его Chromium (`pip install playwright`,
`python3 -m playwright install chromium`):
`python3 browser/visual/tests/chromium_game.py`.
Исходники собственной игры: `tests/wasm/game-core.wat`; воспроизводимая генерация:
`python3 -m pip install wasmtime`, затем `python3 tools/build_game_fixtures.py`.
Обычная сборка проверяет готовые байты через `--check`, компилятор Wasm ей не нужен.
