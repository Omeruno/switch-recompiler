# FreakOut Extreme Freeride 0.7.1

Диагностическая сборка 3D-пути Windows-демо. Оригинальный код x86 выполняется в Unicorn. Он обрабатывает нажатия клавиш, создаёт профиль и загружает сцену главного меню. Захваченный кадр воспроизводится на ПК через OpenGL 4.5 и экспортируется для GPU Nintendo Switch через deko3d.

## Захват кадра из локальной демоверсии

Подготовь распакованную Windows-демоверсию с файлами `FreakOut.exe`, `msvcr71.dll`, `msvcp71.dll`, `filemap.txt`, `Data2.bnd` и папкой `Data/Common/Shaders`. DLL должны находиться рядом с EXE. Для захвата нужен Python 3.10 или новее. Для просмотра PNG нужен Linux с EGL surfaceless и OpenGL 4.5.

В распакованном архиве выполни из каталога `source`:

```sh
python -m pip install -r requirements-3d.txt
python scene_demo.py /path/to/demo/FreakOut.exe /path/to/demo menu-capture
python render_scene.py menu-capture/scene/scene.json menu.png
```

При каждом первом запуске укажи новый выходной каталог. По умолчанию сохраняется 390-й вызов Present. На нём игра уже создала профиль, закрыла окно сохранения и показывает главное меню. Кадр с сообщением `Save successful` можно получить через `--present 270`. В `menu-capture/save/data/user/profile.pro` находится профиль, который записала сама игра. Параметр `--waves` сохраняет на ПК PCM выбранных игрой сэмплов. Во время диагностики звук на Switch не выводится.

## Воспроизведение на Switch

Экспортёр использует компилятор `uam` из devkitPro. Если он есть в PATH, выполни:

```sh
python export_scene.py menu-capture/scene/scene.json main-menu.fos3
```

Можно передать путь к компилятору через `--uam /path/to/uam`. Экспортёр компилирует GLSL в DKSH и сохраняет данные вызовов рисования, включая 3D-геометрию и текстуры из твоей демоверсии.

1. Скопируй папку `switch/FreakOutGpuReplay` из архива в папку `switch` на SD-карте.
2. Положи собранный `main-menu.fos3` рядом с `FreakOutGpuReplay.nro`.
3. В приложении нажми **ZR**, чтобы отрисовать сцену. Кнопка **B** возвращает в диагностику.

NRO воспроизводит выбранный кадр. Интерактивная логика игры по-прежнему выполняется в ПК-диагностике. На физической Switch этот NRO ещё не запускался.

## Что проверено

- Демо дошло до оригинального `Present #390` и записало 31 238 байт профиля. Кадр отрисован через Mesa llvmpipe в 1024×768.
- В основном кадре 102 исходных вызова DrawIndexedPrimitive и 27 текстур. На кадре с окном сохранения было 107 вызовов и 28 текстур. Пять вызовов используют три пары оригинальных программируемых шейдеров. Для Switch упаковано восемь DKSH-модулей, включая шейдеры фиксированного конвейера.
- Проверено 110 исходных ассемблерных шейдеров из демо. Из них 64 DX9 переведены в GLSL и собраны в DKSH. Этот тест подтверждает компиляцию, а визуальная проверка относится к шейдерам, использованным в снятом кадре.
- Обработчик FOS3 проверен на полном кадре и повреждённых пакетах. Ранее экспортированные FOFR прошли свои тесты. Бинарник ARM64 собран чистой сборкой devkitA64.
- Демо прочитало банк музыки из трёх треков. Первый трек декодирован в PCM 44 100 Гц.

```sh
python -m unittest discover -s tests -p '*_test.py'
cc -std=c11 -Wall -Wextra -Werror -I switch tests/scene_packet_test.c \
  switch/scene_packet.c switch/frame_packet.c -o scene-packet-test
./scene-packet-test main-menu.fos3
make -C replay
```

Исходники диагностических инструментов, тестов и NRO находятся в `source`. Пакет кадра создаётся локально из файлов демоверсии.
