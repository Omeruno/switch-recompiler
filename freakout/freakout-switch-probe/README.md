# FreakOut: Extreme Freeride — ARM64-порт для Nintendo Switch

Цель проекта — самостоятельное homebrew-приложение `.nro` для Horizon из Windows-версии игры. Сборщик работает с пользовательской копией игры. Первая веха — проехать один спуск с оригинальной физикой, графикой и звуком, управляя Joy-Con.

## Как собрать отчёт на Windows

1. Распакуй архив и открой PowerShell в папке `freakout-switch-probe`.
2. Впиши свой путь к игре. Для Steam его можно открыть через свойства игры → «Установленные файлы» → «Обзор».
3. Запусти:

```powershell
python .\probe.py "D:\SteamLibrary\steamapps\common\FreakOut Extreme Freeride"
```

Требуется Python 3. Дополнительные пакеты не нужны. Если Python на твоём компьютере открывается через `py`, используй `py -3` вместо `python`. Если в папке несколько файлов `FreakOut.exe`, укажи путь к нужному EXE.

Приложи созданный рядом `freakout-pe.json`. Отчёт содержит относительные имена EXE и DLL, SHA-256, архитектуру, секции, адрес точки входа, таблицы обычных и отложенных импортов и сведения о директориях релокаций и TLS. Скрипт читает файлы как данные. Отчёт не включает байты исполняемых файлов или другие ресурсы игры.

## Как пойдёт порт

1. **Зафиксировать издание.** Для первого прохода выбрана Steam-сборка. По отчёту определим точный SHA-256, архитектуру и зависимости. По таблице PE проверим, можно ли использовать релокации при восстановлении адресов. Динамическую загрузку DLL и методы Direct3D, вызываемые через таблицы COM, потребуется выяснять отдельно.
2. **Получить эталон на ПК.** Снять последовательность запуска до первой трассы, список загруженных DLL, трассу вызовов графики и поведение ввода, звука и сохранений. Для сравнения выбрать один спуск и фиксированные настройки графики.
3. **Перевести код заранее.** Проверить перенос нескольких функций с x86 на ARM64 и сравнить результаты с оригиналом на одинаковых входных данных. Чтобы сохранить 32-битную адресную модель при 64-битном хосте, хранить адреса игры как 32-битные значения и переводить их на границе с платформой. Для косвенных вызовов и таблиц переходов восстановить набор целей. Затем довести переведённый код до стабильной загрузки данных и выхода в меню.
4. **Связать с Horizon.** Файлы, таймеры, потоки и ввод реализовать поверх libnx. Графику подобрать после трассировки: узкая реализация D3D9 поверх deko3d или совместимый слой D3D9 поверх Vulkan. Звуковой слой выбрать после определения FMOD и его фактических функций. Стартовые ролики проверить отдельно.
5. **Проверить на Switch.** На штатных частотах измерить время кадра на одном спуске, начиная с 720p и цели 30 FPS. Проверить стабильность физики, задержку ввода, звук и перезапуск с сохранением профиля. Для 30 FPS бюджет кадра около 33,3 мс. Это цель теста, доступный FPS пока неизвестен.
